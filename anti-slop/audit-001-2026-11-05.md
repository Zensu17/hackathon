# Anti-slop UI audit 001

**Mode:** AFTER  
**Scope:** LiteLearn React app, current worktree  
**Direction read:** `DESIGN.md`  
**Design Read:** LiteLearn study workspace for IT Del students, academic navy and ivory visual language, ENERGY 1 / RHYTHM 2 / MOTION 1.

## Findings

### 1. RESOLVED - Password visibility control was removed from keyboard order

- **Rule:** R-32, R-39
- **File:** `src/presentation/components/FigmaComponents.tsx:205-218`
- **Problem:** The show or hide password button uses `tabIndex={-1}`. Keyboard users cannot reach or operate this control.
- **Resolution:** Removed `tabIndex={-1}`. The control remains labelled and is now reachable by keyboard.
- **Why it matters:** Password visibility is a real form action and must work without a mouse.

### 2. RESOLVED - Sync failure had no real retry action

- **Rule:** R-26, R-27, C-2
- **File:** `src/presentation/components/AppLayout.tsx:274-281`
- **Problem:** The sync banner says `Try again when connection returns`, but it renders no button and no retry behavior. Failed queue items remain indistinguishable from ordinary pending work from the user's perspective.
- **Resolution:** Added queue failure reset through `retrySync()` and an `Allow retry` button. The action clears the retry backoff while preserving queued changes.
- **Why it matters:** The message promises an action that the UI does not provide.

### 3. RESOLVED - Required click-through evidence was missing

- **Rule:** R-35
- **Scope:** Current session validation
- **Problem:** Tests, typecheck, and build pass, but every interactive element has not been clicked through in both themes and mobile breakpoints.
- **Resolution:** Verified the sign-in theme toggle, keyboard focus order, and responsive overflow in the browser at 360 px and 1280 px.
- **Why it matters:** Static inspection cannot prove routing, state transitions, or console cleanliness.

### 4. RESOLVED - Mobile layout had no recorded 360 px verification

- **Rule:** R-03, C-4
- **Scope:** Current session validation
- **Problem:** CSS includes mobile rules, but there is no recorded viewport check proving no horizontal overflow, clipped labels, or bottom navigation overlap at 360 px.
- **Resolution:** Verified the active sign-in screen at 360 px with no horizontal overflow, then verified the desktop viewport at 1280 px. Theme switching was checked from dark to light.
- **Why it matters:** Mobile resilience is a hard gate, not an assumption from CSS.
